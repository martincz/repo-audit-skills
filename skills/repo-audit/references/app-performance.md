# 应用层性能与调用效率审计（`Mode R` · 严格只读）

本规程聚焦应用层代码热路径、跨进程/外部 API I/O 编排、异步并发模型与内存/配额效率，识别会随数据规模、并发量或调用频次显著放大的隐性浪费。

## 1. 审计边界与调用链追踪方法

- **职责分工**：专注**应用层执行效率、外部 I/O 编排与内存计算**；纯数据库索引设计与单条慢 SQL 执行计划归 `references/database-audit.md`，前端纯样式架构归 `references/frontend-ui-audit.md`（仅在应用层循环触发数据库/RPC `N+1` 拉取或前后端串行请求瀑布流时纳入本报告）。
- **先热路径后细节**：优先定位高频 HTTP/RPC 接口、核心批处理/定时同步任务、流式消费 Worker 以及外部 SDK/HTTP/LLM 客户端封装，借助符号工具或调用链检索逐层下钻，忽略冷启动单次脚本的微小对象创建差异。
- **量化放大效应**：每条问题必须标注完整链路 `调用链入口 → 触发位置（文件路径 / 函数符号）`，并用调用次数或时间/空间复杂度公式量化放大机制（例如“每页 $N$ 条记录触发 $2N+1$ 次远端单查，批处理可收敛至 $O(1)$ 次”）；未运行合成基准前绝不杜撰具体毫秒数字。

## 2. 五大检查维度（每类输出 0～3 条最高价值问题）

1. **外部 I/O 未批量化、串行等待与异步事件循环阻塞**
   - 上游 API、对象存储、缓存（如 Redis Pipeline / MGET）或内部服务原生支持批量、范围或分页拉取，代码却在循环中逐条发起网络请求；
   - 彼此无数据依赖的多路外部 I/O 写成顺序串行等待，未使用受控并发聚合；
   - 高频 HTTP/RPC 客户端在每次函数调用内新建连接实例而未复用全局连接池 / Session，反复承受 TCP/TLS 握手开销；
   - **异步反模式**：在异步协程（如 Python `async def`、Node.js 事件循环、Go 高并发热路径）内部直接调用同步阻塞网络请求、同步磁盘读写、子进程等待或重型 CPU 计算，卡死整个事件循环吞吐。

2. **单次调用链内的重复拉取与重复计算**
   - 同一请求生命周期、同一批处理批次或同一调度周期内，上下游函数各自独立重新查询同一份配置/用户/元数据、重复反序列化同一大 JSON，或重复执行昂贵纯计算；
   - 缺乏合理的上下文参数透传或请求级（Request-scoped）轻量缓存。

3. **过度抓取与前置无效计算（Over-fetching & Wasted Work）**
   - 仅需判断记录存在性、统计条数或读取 1～2 个标量字段，却拉取完整大列表、富文本大字段或关联对象图；
   - 在轻量权限拦截、缓存命中检查或条件分支短路之前，就提前完成了全量数据加载、深层对象构造或重型解析，导致后续分支直接丢弃计算结果。

4. **热路径算法复杂度、内存拷贝与流式处理缺失**
   - 大集合上的嵌套循环关联（$O(N \times M)$，未先构建哈希字典/集合索引做 $O(1)$ 查找）、高频热路径上对长 `list` 做线性 `in` 成员扫描；
   - 循环内高频字符串/字节流拼接、大数组/DataFrame/大字典反复深拷贝（`deepcopy`）或全量重排；
   - 导入导出、日志解析、大文件上传下载或大响应体拉取时一次性全量读入内存（易随文件增大直接触发 OOM），未采用迭代器/分块流式（Streaming / Chunked）处理。

5. **重试风暴、并发失控与外部/LLM 配额放大**
   - 外部调用缺乏显式连接与读取超时、缺乏并发上限信号量（Semaphore）或缺乏指数退避与抖动（Jitter），在下游变慢或返回 `429/503` 时引发级联重试风暴，成倍放大延迟与配额消耗；
   - 热点缓存失效瞬间缺乏请求合并（Singleflight / 互斥回源）保护，导致并发请求同时击穿至慢速上游；
   - **AI / LLM 与 Embedding 调用效率**（若项目涉及模型调用）：逐条串行请求 Embedding 而未按批次聚合；将每次变化的时间戳、随机 ID 或动态会话状态拼在长系统提示词最前面，破坏服务端 Prompt Caching 前缀命中；工具调用循环缺少最大轮数与 Token 预算硬上限。

## 3. 输出与等价性保障要求

按 `SKILL.md` 通用契约输出各维度问题与收尾四档优先级清单（`P0` / `P1` / `Quick Win` / `P2`）。在每条「改进方案与验证方法」中，必须明确说明**优化后如何保持原有业务语义不变**（如批量化后的结果顺序对齐、部分失败时的错误隔离、受控并发上限设定、请求级缓存的作用域生命周期防跨用户串数据），并给出 1 条回归验证或纯内存合成基准对比方法。
