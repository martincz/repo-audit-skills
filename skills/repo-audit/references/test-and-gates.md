# 测试套件精简、覆盖缺口与门禁优化蓝图（`Mode R` · 严格只读）

本规程对项目的测试套件（如 `tests/`、`__tests__/`、`*.spec.*`）及提交与持续集成门禁（如 `.pre-commit-config.yaml`、`.githooks/`、`.git/hooks/`、`scripts/`、CI 配置）执行只读体检，消除 AI 迭代累积的低价值碎片测试与阻塞慢点，补齐高危测试盲区，并设计秒级增量 `pre-commit` 门禁方案。

## 1. 严格只读与实测基线采集规则

- **全程只读（`Mode R`）**：不修改、合并或删除任何测试文件与钩子脚本；输出完整《测试精简、缺口补齐与门禁分层蓝图》供人工审阅拍板后再分批执行。
- **先读约定，再采基线**：
  1. 先读取 `AGENTS.md`、测试配置（如 `pyproject.toml`、`pytest.ini`、`vitest.config.*`）与现有钩子脚本，摸清项目既有的测试分层约定（如默认无外部依赖快测、架构边界测试、需真实数据库/网络的集成验收），确保蓝图不破坏既有分层契约。
  2. **安全沙箱实测优先**：若当前环境可在不连接外部真实服务、不污染本地状态的前提下安全运行默认单测集，执行只读计时采样（如 `pytest --durations=30 -q` 或等价命令），记录真实测试文件数、总用例数、总耗时、最慢 Top 20 用例及核心模块覆盖率（若已装覆盖率工具），并拆解当前 `pre-commit` 各步骤耗时。
  3. **受限自动降级**：若沙箱缺依赖或测试需外部基础设施而无法运行，在开头如实记录边界并自动降级为源码与配置静态剖析，绝不编造耗时或覆盖率数字。

## 2. 测试去留、补缺与提速标尺

### A. 锁死不动的核心红线测试（严禁为提速建议删减或弱化断言）
1. 全局架构与治理契约门禁测试（如模块单向依赖边界 `test_boundary`、数据生命周期全表注册契约、启动安全配置自检）；
2. 认证鉴权、会话归属、多租户数据隔离、越权拦截与加密安全边界测试；
3. 真实线上故障复现回归、并发竞态、崩溃恢复、幂等重试与核心业务计算口径（如时点对齐、精确舍入、同源等价性）回归测试。

### B. 重点治理的四类 AI 累积膨胀测试
1. **补丁式碎片测试（归并 + 表驱动参数化）**：按临时 Bug 单号或单次修补命名的零散微测试文件，或围绕同一目标函数复制粘贴大段相同前置构造代码的相似用例 → 建议归并入对应业务域标准测试模块，合并为清晰的 `@pytest.mark.parametrize` / `test.each` 表驱动用例。
2. **重度 Mock 镜子测试（改写为行为契约或清理）**：把被测函数内部私有辅助调用全部 `mock` 打桩、仅断言内部函数调用次数/顺序却不验证外部可观测返回值或状态结果的脆弱测试（一重构内部实现就红，真出逻辑 Bug 却绿）→ 优先建议改写为基于纯内存输入与轻量假适配器（Fake）的行为契约测试；若其有效路径已被上层真实行为测试完整覆盖，建议直接清理。
3. **跨层全排列重复枚举（收窄上层职责）**：底层纯领域函数已通过参数化完整穷举过的细碎边界组合，无需在慢速 HTTP 路由或 CLI 子进程集成测试中再重跑一遍笛卡尔积，上层集成测试聚焦路由连通、序列化契约、状态码与权限拦截。
4. **零价值语法/脚手架凑数测试（直接清理）**：仅断言语言原生语法、常量等于自身、简单 Getter/Dataclass 字段赋值或第三方库自带行为的无意义用例。

### C. 单测内部提速与高危测试缺口双向排查
- **消除内部人为慢点**：排查单测中的真实阻塞等待（如 `time.sleep` / `setTimeout` 硬等待），建议改为可注入时钟、时间冻结（monkeypatch）或确定性同步事件；识别每个用例重复初始化的高开销纯只读合成数据夹具（Fixtures），建议在严守写状态隔离的前提下合理提升只读夹具作用域。
- **高风险核心路径测试真空补齐**：对照核心业务域、资金/核心口径计算、权限边界与幂等异常回滚路径，指出当前完全缺乏自动化断言保护的高危盲区（聚焦最高风险 0～5 处，不求形式覆盖率数字）。

## 3. Pre-commit 与验证门禁优化准则

1. **秒级增量守门（聚焦拦截坏提交，不阻塞开发心流）**：
   - 格式化、Linter 与类型检查优先仅针对本次暂存（staged）文件或受影响包增量运行；前端资源构建检查仅在前端源码/模板/样式文件发生变更时触发。
   - `pre-commit` 中的测试策略采取 **「必跑极轻量全局契约测试 + 按暂存改动路径映射关联的 `fast` 单元测试」**（当改动命中公共基础层、全局配置或测试夹具时，自动升级运行核心快速回归集），避免改一两行局部业务代码或纯文档就全量串行重跑全部慢速集成测试。
2. **慢测显式分层不漏检**：
   - 将涉及子进程拉起、重型容器/数据库 I/O、大批量合成压测的慢速用例通过明确标记（如 `slow` / `integration`）隔离，固定保留在 `pre-push` 钩子或收口全量验收 / CI 流水线中执行，做到“日常提交秒级反馈、合入发布全量兜底”。

## 4. 必输交付物：《测试精简、缺口补齐与门禁分层蓝图》

报告严格按以下 5 个章节依次输出：

1. **现状基线与耗时瓶颈拆解**：当前测试文件数、总用例数、总耗时、核心模块基线覆盖率（若实测可得）、最慢 Top 10 瓶颈根因，以及当前 `pre-commit` 典型改动下的各环节耗时拆解。
2. **测试文件与用例瘦身处置总表（Markdown 四列表格）**：列为 `动作（参数化合并 / 归口迁移 / 消除真 sleep 与慢夹具 / 改写重度 Mock / 删除纯冗余）` | `涉及测试文件与用例符号` | `冗余、脆弱或低效的代码证据` | `等价覆盖保障（由哪条保留或合并后的用例继续兜底）`。
3. **高风险核心测试缺口补齐清单（0～5 条）**：仅列一旦出错代价最高却缺乏有效测试的核心业务逻辑或安全边界，附建议验证场景。
4. **明确锁死不动的红线测试清单**：列出识别出的架构契约、安全隔离与关键回归测试文件，确认后续瘦身执行时断言强度不打折。
5. **Pre-commit 与全量门禁分层改造方案**：以对照表列出改造前后的触发条件（纯文档改动 / 后端单模块改动 / 前端改动 / 公共底层改动）、`pre-commit` 秒级命令、`pre-push` 或全量验收命令及预期提速收益。
