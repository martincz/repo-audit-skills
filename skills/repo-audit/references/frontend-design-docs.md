# 设计规范与产品文档重构（`Mode W-Doc` · 仅改规范文档）

本规程用于梳理并建立项目的权威前端设计与产品规范体系（`PRODUCT.md`、`DESIGN.json`、`DESIGN.md` 及关联指导文档），在保留既有成熟产品气质的前提下消除历史杂乱硬编码与多文档冲突，建立可供人类开发者及 `frontend-design`、`impeccable` 等外部前端实现类 Skill 直接遵循的单一事实源（SSOT）。

## 1. 严格写权限边界与生态借力原则

1. **严守 `SKILL.md` 的 `Mode W-Doc` 安全门禁**：
   - 修改前先运行 `git status` 检查工作区未提交变更风险；
   - **严锁文件修改白名单**：本轮**仅允许创建或重构 `PRODUCT.md`、`DESIGN.json`、`DESIGN.md`，以及仓库内已存在的前端规则引用文件（如 `web/AGENTS.md`、`.impeccable.md` 等）中的冲突或引用条款**；
   - **绝不修改任何业务源码、页面模板、前端组件、JS/TS 或 CSS/Tailwind 样式文件**（确保设计标准先经人工审阅拍板，后续再分批交由前端实现流程按页落地）；
   - 完成后停留在本地工作区供人工审阅 `diff`，不自动执行 `git commit` 或 `git push`。
2. **演进收敛与采优去杂（防止把脏现状抄成标准）**：
   - 从项目现有**最成熟、最统一的核心页面与全局样式配置**中提炼并扶正既有视觉风格，不脱离产品定位凭空发明全新风格；
   - 同时严格甄别淘汰早期遗留的偶然硬编码——不将存量代码中散乱的野生像素字号、相近重复色号或局部 `!important` 妥协原样照搬进 `DESIGN.json`。
3. **外部前端生态 Skill 协同 + 真实渲染采样自动降级**：
   - 先检查宿主是否已挂载 `frontend-design`（Anthropic 官方）、`impeccable`、`chrome-devtools` 等配套 Skill：若已挂载，直接参考其界面模式分类（如 `Operate` 工作台、`Persuade` 营销页、`Read` 文档页）与反 AI 模板化标尺，无需在 `DESIGN.md` 中重复抄写长篇通用前端常识；
   - 若具备浏览器调试工具且本地前端服务可访问，优先在「桌面端 + 移动端」「浅色 + 深色主题（若支持）」下采样核心页面的真实计算样式（字号、字重、行高、间距、对比度），识别成熟基准写法与层级错乱反例；若工具不可用或服务未启动，自动降级为基于样式配置与核心组件源码的静态采样并在收尾说明，不中途停等。

## 2. 文档职责切分（单一事实源 SSOT，杜绝重复抄写）

若目标文档尚不存在则按职责新建，若已存在则就地重构去重：

1. **`PRODUCT.md`（产品定位与页面信息优先级契约）**
   - 明确产品的业务定位、核心受众、主要使用场景及各核心页面的界面模式（如高频操作工作台 `Operate` vs 宣传转化页 `Persuade`）。
   - 为核心页面/模块建立明确的**三级业务信息优先级（Information Hierarchy）**：
     - `L1`：核心结论、首要状态信号或主 KPI 数值；
     - `L2`：支撑维度、对比指标、筛选控件与主表核心数据；
     - `L3`：口径注释、时间戳、次要分类标签与辅助提示。
   - **纯业务边界**：以此作为 UI 决定“谁大、谁小、谁突出”的唯一业务依据，**不在 `PRODUCT.md` 中写入具体像素值、色号或 CSS/Tailwind 类名**。

2. **`DESIGN.json`（机器可读的 Design Tokens 唯一数值源）**
   - 采用清晰的三层结构组织：
     - `primitive`：基础字阶、行高刻度、4/8px 间距阶梯、圆角刻度、基础色板；
     - `semantic`：浅色/深色主题下的背景与表面层级（Surface Elevation）、多级文本对比度色、边框强弱色、通用反馈状态色（成功/警告/错误/信息）、**结合当前项目真实领域的专属语义色**（例如运维监控的告警等级色、金融行情的涨跌持平色等）、以及语义排版角色组合；
     - `component`：按钮、输入框、选择器、分段切换（Tabs）、表格行/表头、卡片、弹窗/抽屉、胶囊徽章（Badge）的统一尺寸档位（如 `sm` / `md` / `lg`）。
   - 明确标注每个语义 Token 与项目现有 CSS 变量或 Tailwind 工具类的映射关系，确保后续可直接用于代码收敛。

3. **`DESIGN.md`（面向开发者与 AI Skill 的可执行设计宪法）**
   - 直接引用 `DESIGN.json` 中的语义 Token 键名，不另起炉灶散落硬编码数值。
   - 完整建立第 3 节规定的五项核心规范，并附上简明清晰的「推荐正例 vs 禁用反例」。

4. **存量前端指导文件对齐（如已存在的 `web/AGENTS.md`、`.impeccable.md`）**
   - 清理其中与新版三文档冲突或重复抄写的旧样式硬规则，改为按需引用 `PRODUCT.md`、`DESIGN.json` 与 `DESIGN.md`，不保留第二套易漂移的副本。

## 3. `DESIGN.md` 必须确立的五项核心规范

1. **语义排版阶梯与“反倒挂”铁律**
   - 将全站零散字号收敛为有限、职责唯一的语义角色（覆盖：页面主标题、区块标题、卡片/弹窗标题、核心 KPI/主数值、正文与主表数据、常规交互控件文本、表头与字段名 Label、辅助注释/时间戳/胶囊徽章 Badge），逐一规定「Token 键名 · 字号 · 行高 · 字重 · 默认文本语义色 · 适用场景 · 禁用场景」。
   - 写入硬性**综合视觉权重（`字号 × 字重 × 颜色对比度`）单调递减不变量**：子级标题视觉重量绝不大于父级标题、字段标签（Label）绝不抢夺字段值（Value）焦点、辅助注释与胶囊徽章绝不重于正文或卡片标题。

2. **中西混排与专业数据排版专规（按项目业务领域适配）**
   - 规定中文及多语言在桌面端与移动端的可读最小字号底线（防止小字号发虚粘连），区分单行紧凑控件与多行阅读正文的行高标准。
   - 对高频数值、表格数据、百分比、金额、日期与编号统一强制等宽数字对齐（`font-variant-numeric: tabular-nums`）；明确「主数值 + 单位（如 `%`、`ms`、货币或量级单位）」的字号/对比度降档规则，以及空值占位（如 `—`）、正负号与项目领域语义色的统一表达。

3. **版式纪律、控件族统一与防视觉抖动（CLS）**
   - 规定全站控件族的统一尺寸档位、内边距节奏、克制圆角（操作工作台卡片圆角保持紧致，严禁卡片套卡片、普通通栏区块滥用悬浮卡片或添加无意义背景渐变光斑）及焦点/悬停/加载/禁用态过渡标准；
   - 要求纯图标控件必须附带悬停提示（Tooltip）与无障碍名称，统一使用项目标准图标库而非手写零散内联 SVG；
   - 针对异步局部更新与图表/数据重绘，明确骨架屏或固定占位尺寸约束以消除布局跳动（CLS）。

4. **桌面端信息密度 vs 移动端适配标准**
   - 明确响应式断点职责：桌面端保持与界面模式匹配的紧凑有效信息密度与宽屏最大容器约束；移动端规定字阶缩放规则、宽表格/多列指标的降级展示方案及最小可触控热区（`≥ 44×44px`）。

5. **面向 `frontend-design`、`impeccable` 等外部 AI 设计 Skill 的显式协作护栏**
   - 在 `DESIGN.md` 醒目位置写入 **AI 设计 Skill 协作边界声明**：后续任何 UI 新建、审计修复或精修任务（无论由人工还是 `frontend-design` / `impeccable` 执行），必须严格服从本项目的既有视觉气质、`PRODUCT.md` 信息分级、`DESIGN.json` 令牌阶梯与现役公共组件体系；将设计能力聚焦于「理顺视觉层级、对齐网格间距、收敛硬编码 Token 与打磨交互状态」，禁止擅自引入脱离产品定位的装饰字体、在操作工作台塞入营销落地页式超大标题/大留白、或违背项目领域语义的野生配色。

## 4. 交叉核验与收尾审阅摘要

1. **确定性核验**：修改完成后运行 `python3 <skill-dir>/scripts/verify_governance.py --root <target-repo-root>`（无 Python 环境则手动核对），确保 `DESIGN.json` 语法合法、引用的仓库文件路径全部真实存在，且 `PRODUCT.md` 分级、`DESIGN.json` 键名与 `DESIGN.md` 规则三者 100% 对齐无冲突。
2. **输出三项人工拍板摘要**：
   - **文档重构摘要**：简明说明新增、修正或清理了哪些冲突条款，以及从哪些现有成熟页面提炼了基准风格；
   - **全站语义字号与层级速查表（Markdown 表格）**：完整展示新建的「语义角色 → Token / 字号 / 行高 / 字重 / 颜色层级 → 典型页面元素」对照表，方便快速审阅尺度；
   - **存量页面典型偏离样本（Top 5～8 处）**：列出采样中发现的最典型层级倒挂或硬编码绕过位置（附真实文件路径，仅作为标准确认后下一阶段交由前端改造的起点，本轮绝不改代码）。
