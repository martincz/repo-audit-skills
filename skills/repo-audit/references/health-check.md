# 全局项目健康初筛（`Mode R` · 严格只读）

本规程用于对代码仓库执行一次全景式、高信噪比的只读健康体检，产出可直接用于技术债排期修复的初筛报告，并为深水区系统性问题精准分流。

## 1. 定位与专项分流边界

- **严格继承 `SKILL.md` 的 `Mode R` 只读门禁与全局输出契约**。
- **全局初筛定位**：优先覆盖核心业务链路、认证入口、数据访问层、构建部署配置与测试门禁，抓出最影响系统安全、正确性、稳定性与演进效率的关键隐患，忽略代码排版或局部命名偏好。
- **深水区专项转交**：若在初筛中发现某领域存在系统性痛点，仅在本报告对应维度记录最关键的 1～2 个代表性症状，并在「改进方案」中明确注明建议进一步调用本 Skill 下的对应专项深挖：
  - 复杂鉴权/越权/供应链隐患 → `references/security-boundary.md`
  - 大面积过度设计或复杂并发异常 → `references/code-quality.md`
  - 目录职责混乱与循环依赖 → `references/module-structure.md`
  - 全站样式割裂、字号倒挂或换肤困难 → `references/frontend-ui-audit.md`
  - 慢 SQL、索引缺失或历史表无限膨胀 → `references/database-audit.md`
  - 外部 API 串行阻塞、重复计算或配额浪费 → `references/app-performance.md`
  - 测试套件臃肿缓慢或钩子卡顿 → `references/test-and-gates.md`
  - `AGENTS.md` / 项目 Skills 陈旧漂移 → `references/agent-docs-business.md`

---

## 2. 六大检查维度（每类输出 0～3 条最高价值问题）

1. **安全性与权限隔离**
   - 路由/接口鉴权遗漏、对象级或多租户数据边界未隔离、硬编码密钥/凭据、未校验的外部输入（注入/SSRF/路径穿越）、敏感信息写入日志或响应体。
2. **正确性与稳定性**
   - 核心业务口径计算错误、空值/精度/时区边界缺陷、静默吞异常掩盖故障、并发竞态或非原子多步状态更新导致的数据不一致、崩溃后无法安全重试。
3. **性能与资源效率**
   - 显著的数据库 `N+1` 查询或无索引全表扫描、高频接口串行外部 I/O 或异步事件循环同步阻塞、大对象全量加载引发内存压力、缺失超时与并发上限控制。
4. **架构设计与可维护性**
   - 核心模块循环依赖、跨层职责混杂（如路由层直写复杂业务与底层 SQL）、关键业务规则多处复制粘贴导致修改漏同步、妨碍演进的过度耦合。
5. **测试与可验证性**
   - 资金/权限/核心状态流转等高风险路径缺乏自动化测试保护、重度脆弱 Mock 导致重构即碎却抓不住真 Bug、本地或 CI 缺乏可靠的回归验证入口。
6. **工程与配置管理**
   - 锁文件缺失或高危依赖、环境变量/默认配置回退隐患（如默认开启调试或宽松权限）、构建/容器/部署脚本脆弱点、关键故障缺少可观测日志与错误追踪。

---

## 3. 输出结构

1. **审计范围与验证边界说明**（分支/提交号、覆盖模块、实际运行的无副作用检查与未覆盖边界）。
2. **六大维度逐类审计结果**（每条含：问题标题 + `[已复现]`/`[已实测]`/`[静态推断]`、涉及位置、现状与风险、改进方案与 1 条关键回归验证场景、预估改动成本）。
3. **分阶段修复优先级总表**（`P0` / `P1` / `Quick Win` / `P2`，含排序理由与建议切入点）。
