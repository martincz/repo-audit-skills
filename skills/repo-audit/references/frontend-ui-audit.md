# 前端 UI/UX、样式架构与设计一致性审计（`Mode R` · 严格只读）

本规程聚焦存量 Web 项目的**全站视觉一致性、信息层级准确度、Token 换肤维护成本与多端交互可用性**，输出去主观审美的客观架构与体验审计报告。

## 1. 生态联动、设计基准与验证策略

1. **严格只读（`Mode R`）**：不修改任何组件、模板、样式或设计文档；若项目尚无规范文档且用户希望直接建立 `PRODUCT.md` / `DESIGN.json` / `DESIGN.md`，应在报告中提示或按用户指令切换至 `references/frontend-design-docs.md`。
2. **外部前端生态 Skill 协同优先（避免重复造轮子）**：
   - 执行前先检查宿主环境已挂载的可用 Skills：
     - 若存在 `frontend-design`（Anthropic 官方）、`impeccable` 或 `web-design-guidelines`：直接读取并复用其「AI 生成套路识别（Anti-Slop Calibration）、界面模式语义与面向用户的动词文案标准」，无需凭主观印象评判；
     - 若存在 `chrome-devtools`、`a11y-debugging` 或 `debug-optimize-lcp`：在本地开发服务可访问时，直接复用其浏览器快照、无障碍语义树、对比度与渲染抖动检查流程。
   - 若宿主未挂载任何外部前端 Skill，则以第 2 节内置的客观可量化规则作为完整评估基线。
3. **项目既有三文档标尺优先**：
   - 先检查仓库是否存在 `PRODUCT.md`（页面 L1/L2/L3 信息优先级）、`DESIGN.json`（Design Tokens 唯一数值源）、`DESIGN.md`（设计宪法与反倒挂规则）及前端目录 `AGENTS.md` / `.impeccable.md`。
   - 若存在，以其为权威标尺稽查代码实现是否偏离（如绕过 Token 散落硬编码色值/字号，或违反信息优先级）；若文档自身前后打架或与成熟核心页面脱节，一并指明。
4. **真实浏览器渲染优先 + 无缝静态降级**：
   - 若当前环境具备浏览器工具（如 Chrome DevTools / Playwright）且本地前端服务已运行，优先在「桌面端 + 移动端视口」与「浅色 + 深色主题（若支持）」下实测计算样式、溢出与焦点状态，标注 `[已实测]`；
   - 若无浏览器工具或本地服务未启动，在开头说明验证边界并自动降级为模板/组件/CSS/Tailwind 配置静态审查，标注 `[静态推断]`，不中途停下询问。

## 2. 六大检查维度（每类输出 0～3 条最高价值问题）

1. **界面模式契合度与版式结构硬规则**
   - **界面模式错位**：区分操作工作台/业务后台（`Operate`：应克制、紧凑、高可扫读性、以浅表面层级差替代粗黑重边框，忌塞入营销落地页式的超大装饰横幅与大留白）与营销/展示落地页（`Persuade`：首屏须严控元素预算，突出品牌/核心价值与真实可检视视觉素材，忌用廉价渐变块或空洞占位图充当主角）；
   - **结构反模式**：严查**卡片套卡片（Nested Cards）**、把普通通栏页面区块硬包进悬浮卡片、密集业务工作台使用过大松散圆角（无既有规范时卡片圆角宜紧致克制，通常 ≤8px），以及无信息价值的背景渐变球/光斑装饰（gradient orbs / bokeh blobs）。

2. **视觉层级单调递减与专业数据排版**
   - **反倒挂铁律**：核查综合视觉权重（`字号 × 字重 × 颜色对比度`）是否严格服从业务信息分级（L1 核心结论/主指标 > L2 支撑维度/主表数据 > L3 辅助注释/时间戳/胶囊徽章），揪出“字段标签（Label）视觉重于字段值（Value）”“子标题重于父标题”“次要状态胶囊比正文更抢眼”等层级倒挂；
   - **字阶与数据对齐**：排查绕过 `DESIGN.json` / Tailwind 主题令牌的零散硬编码字号与色值；检查中文移动端最小可读字号底线，以及表格数值、金额、百分比、编号与时间列是否启用等宽数字对齐（`font-variant-numeric: tabular-nums`）。

3. **控件族全站统一性、图标规范与交互微动效**
   - 按钮、输入框、选择器、分段切换（Tabs）、表格、卡片、弹窗/抽屉、徽章在全站各路由下的高度档位、内边距节奏及悬停/焦点/加载/禁用态是否一致；
   - 排查手写粗糙内联 SVG 混用问题（应统一使用项目标准图标库），核查**纯图标按钮是否缺失悬停提示（Tooltip）与无障碍名称（`aria-label`）**；
   - 动效是否克制且服务于用户操作反馈（展开、确认、视图切换），而非全页泛滥的机械淡入上浮。

4. **组件复用、样式解耦与主题换肤成本**
   - 同类 UI 结构是否在多页面复制粘贴导致改一漏十；业务状态逻辑是否与具体表现层类名死绑；
   - 是否滥用 `!important`、行内写死样式或过深选择器覆盖来强压局部样式；
   - 背景表面层级、文本对比度阶梯、边框强弱与领域语义色是否抽离为语义化 CSS 变量 / Design Tokens，评估完善深浅色切换或整体换肤时的真实卡点。

5. **响应式布局与多端可用性（桌面端 & 移动端）**
   - 断点职责是否清晰；移动端视口下是否存在横向滚动溢出、弹窗/下拉框截断遮挡、多列表格未做滚动或卡片降级、以及可点击控件触控热区过小（小于 `44×44px`）；
   - 桌面宽屏下是否存在容器无限拉宽导致阅读视线断裂，或核心工作区信息密度失衡。

6. **核心 UX 闭环、防布局抖动（CLS）与无障碍基线**
   - 加载态、空状态（是否给出明确的下一步行动引导而非冷冰冰空白）、错误提示（是否用面向用户的清晰语言说明原因与修复动作，按钮文案是否使用明确动词如“保存更改”而非含糊“提交”）及表单防重复提交；
   - 异步数据加载、局部刷新（如 SPA 状态切换、htmx 局部替换、图表/图片渲染）是否预留稳定占位尺寸以消除视觉跳动（CLS）；
   - 键盘 `Tab` 焦点环可见性、`prefers-reduced-motion` 尊重情况，以及文字对比度缺陷（WCAG 正文 ≥4.5:1，大字号标题与关键 UI 边界 ≥3:1）。

## 3. 下游落地友好型输出要求

按 `SKILL.md` 通用格式输出每条问题（注明具体路由 / 组件模板文件 / 样式类或 Token）与收尾四档优先级表（`P0` / `P1` / `Quick Win` / `P2`）。在每条「改进方案」中明确写出**建议收敛到的目标 Token 键名、CSS 变量或公共组件路径**，以便人工确认后可直接将该条目移交 `frontend-design` 或 `impeccable` 等前端实现类 Skill 按章改码。
