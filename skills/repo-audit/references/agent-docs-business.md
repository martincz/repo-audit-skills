# `AGENTS.md`、Skills 与项目开发文档重构（`Mode W-Doc` · 面向普通业务仓库）

本规程用于审计并直接重构**普通业务应用/服务仓库**中的所有 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、`.agents/rules/`、项目级 Skills（如 `.agents/skills/`、`.claude/skills/`）及内部开发指导文档，使其符合高自主性推理模型（兼容 Codex / Claude / Gemini 等主流 Coding Agent）的现行最佳实践。

> **适用分流**：若目标仓库本身是以 Agent Skills、提示词库、Subagents 或多智能体框架为核心交付产物的仓库，请改读 `references/agent-skills-framework.md`。

## 1. 安全修改门禁与仓库边界

严格遵循 `SKILL.md` 的 `Mode W-Doc` 门禁：
- **Git 干净基线与停靠**：修改前先运行 `git status` 确认无未提交冲突风险；全部重构与校验完成后停留在本地工作区供人工审阅 `diff`，**不自动执行 `git commit` 或 `git push`**。
- **修改范围锁死**：仅直接修改当前仓库内的 Agent 规则文档、开发指导文档与项目级 Skills，保持项目原有业务代码与目录结构不变；可只读检查宿主全局配置或外部已安装 Skills 排查触发或规则冲突，但**只报告冲突，绝不修改目标仓库之外的任何文件**。

---

## 2. 真实源码对账与去噪防漂移

1. **对照实现修剪死路径与旧命令**：核对当前真实目录结构、包管理清单（如 `package.json`、`pyproject.toml`、`Cargo.toml`、`go.mod`）、Makefile/脚本、CI 配置与环境变量定义，修正或删除已不存在的文件路径、废弃命令、过期配置项和与现行代码脱节的架构描述。
2. **消除多源重复与底层冗余**：合并 `AGENTS.md`、`CLAUDE.md` 与 `README.md` 之间大段重复抄写或前后矛盾的段落；删除现代 Coding Agent Harness 已经原生内置的基础工具使用废话；严格区分“已核实的失效/冲突问题”与“个人行文风格偏好”，不做无实质收益的同义词替换。

---

## 3. 面向高自主性推理模型的六大重构原则

1. **`AGENTS.md` 按需路由替代全局强制通读**
   - 删除“每次任务开始前必须先完整阅读所有架构/数据库/API/部署文档”等浪费上下文窗口的全局指令；
   - 改为清晰的**按任务类型或改动目录条件触发索引**（例如：“涉及 Schema 或迁移改动时，先阅读 `docs/database.md`；涉及前端组件时，参考 `DESIGN.md`”），将冗长操作步骤下沉至对应子文档或项目级 Skill。

2. **项目级 Skill 基础合规与渐进式披露**
   - 核对仓库内项目级 `SKILL.md` 满足 `agentskills.io` 规范：`name` 与父目录同名且仅含小写字母、数字和单连字符（≤64 字符）；`description` 非空且 ≤1024 字符，清晰写明**适用场景与不适用边界**，消除不同 Skill 之间的触发词重叠；
   - 复杂项目级 Skill 采取渐进式加载：根 `SKILL.md` 聚焦路由与核心不变量（`<500` 行），详细参考与确定性辅助脚本下沉至 1 层深度的 `references/` 与 `scripts/`。

3. **重型或高风险流程的显式调用控制**
   - 对于生产发布、数据库破坏性变更、全量重跑等仅适合人工主动触发的重型项目级 Skill，补充显式调用控制以避免模型隐式误触：
     - 保持 `SKILL.md` 顶部 YAML 仅使用 `agentskills.io` 标准字段以确保跨端校验通过；
     - 针对 Codex / ChatGPT 添加侧车 `agents/openai.yaml` 并设置 `policy.allow_implicit_invocation: false`；若项目明确仅面向 Claude Code 单一生态，可按需使用 `disable-model-invocation: true`。

4. **清理旧模型思维脚手架与自相矛盾规则**
   - 删除要求模型在正文输出逐步思考过程、每执行一步都先复述完整计划、或反复机械催促“写完代码记得检查语法”的过时脚手架（现代推理模型已具备深度内部推理链；仅保留项目特有的真实校验命令入口）；
   - 排查并消除让推理模型空耗推理 Token 的自相矛盾指令（如一边要求“不遗漏任何细微可能”，一边要求“回复不超过三句话”）。

5. **软化引发过度停顿的高压措辞，完整保留核心安全红线**
   - **核心红线 100% 保留并补充简短原因（Why）**：涉及数据安全、多租户权限隔离、生产环境边界、密钥保护、核心业务/财务计算不变量等硬约束必须完整保留，并用简短子句说明背后的风险原因，帮助推理模型在未穷举的边缘场景正确泛化。
   - **将笼统“严禁/绝不”改写为「自主白名单 + 例外询问边界」**：把容易导致高自主模型在常规安全操作上频繁停下反问的粗糙禁令，重构为：
     - **可直接自主执行的安全操作**：只读检索与分析、局部代码实现、运行本地 Linter/类型检查/单元测试、修复常规报错并复验；
     - **必须停下确认的明确例外**：破坏性删除或不可逆迁移、触碰生产环境或真实外部付费/写接口、引入新的重型第三方依赖、或业务需求存在多解分叉未决时。

6. **明确指令优先级、完成标准与跨模型兼容**
   - 声明清晰的优先级链：`核心安全与数据红线` > `用户当次明确指令` > `项目常规工作流与 Skill 默认约定`；
   - 明确端到端完成标准——完成代码/文档修改、运行对应本地验证命令、处理普通报错并复验通过后再交付，避免刚写完初版就半途停下等待催促；
   - 保持跨 Codex / Claude / Gemini 兼容的清晰架构表达，不为单一模型特性堆砌脆弱的通用 Prompt 技巧。

## 4. 收尾交叉校验与实证变更摘要

1. **确定性验证**：修改完成后运行 `python3 <skill-dir>/scripts/verify_governance.py --root <target-repo-root>`（无 Python 环境则手动逐条核查），确认所有引用路径、脚本入口、配置键与 `SKILL.md` 元数据真实合法；若条件允许且无副作用，顺手验证文档中记载的静态检查/帮助命令是否可用，发现漂移继续修平。
2. **输出四项实证摘要**：
   - ① **清理的失效内容、冲突条款与旧模型脚手架**；
   - ② **软化或重构的安全自主操作边界**；
   - ③ **完整保留的核心安全与业务红线**；
   - ④ **检出的仓库外/宿主全局配置冲突（如有，仅报告未修改）**；
   并在末尾明确区分「已实际运行验证的项」与「仅做源码静态核对的项」，不宣称未经实测的效果数据。
