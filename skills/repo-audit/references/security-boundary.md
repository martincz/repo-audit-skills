# 安全、信任边界与供应链审计（`Mode R` · 严格只读）

本规程聚焦代码仓库的真实攻击面与权限信任边界，识别可被利用的越权、泄露、注入、重放与供应链风险。

## 1. 审计前置：建立信任边界地图

严格遵守 `SKILL.md` 的 `Mode R` 只读门禁（不探测真实外部服务、不读取或打印真实密钥明文，发现疑似硬编码凭据时仅引用文件路径与变量名并打码展示）。深入源码前，先快速理清四类入口边界：
- 未认证公开入口（登录、注册、公开查询、静态文件、开放回调）；
- 普通认证主体边界（当前登录用户、所属组织/租户、API Key 作用域）；
- 高权限管理与内部运维入口（Admin 路由、内部 RPC、CLI/定时脚本、调试端点）；
- 不可信外部数据回流边界（第三方 Webhook、OAuth 状态回传、用户上传文件、爬虫/外部网页内容、LLM 生成结果）。

---

## 2. 六大检查维度（每类输出 0～3 条最高价值问题）

1. **认证、会话安全与对象级/多租户越权（AuthN / AuthZ / IDOR）**
   - 新增或边缘路由/RPC 是否漏挂鉴权中间件，或被通配白名单意外放行；
   - 读写删操作是否仅校验“已登录”，却直接信任客户端传入的 `user_id` / `org_id` / 资源 ID 而未与当前会话主体做归属绑定（水平越权 IDOR 与跨租户泄漏）；
   - 功能级权限是否仅在前端隐藏按钮而后端未强制拦截（垂直越权）；
   - Session / JWT / Cookie 是否缺失过期淘汰、密码/权限变更后旧令牌失效机制，以及 `HttpOnly` / `Secure` / `SameSite` 安全属性。

2. **密钥凭据、加密原语与日志/错误脱敏**
   - 源码、默认配置、测试夹具或前端打包产物中是否硬编码私钥、API Secret、管理口令或高权限连接串；
   - 安全令牌、重置验证码或签名盐值是否误用非密码学伪随机数，密码哈希或敏感字段加密是否采用过时弱算法；
   - 未捕获异常响应、审计日志、埋点或调试输出是否泄露内部堆栈路径、SQL 原文、Authorization 头、Session Token 或用户隐私数据（PII）。

3. **注入、SSRF、文件处理与客户端跨站边界**
   - SQL、Shell 命令（如子进程拼接参数）、代码执行或服务端模板是否存在外部可控输入拼接；
   - 服务端代发 HTTP/Webhook/头像抓取/文档解析功能是否允许用户控制目标 URL 且未限制协议与内网/云元数据网段（含 DNS 重绑定与 30x 重定向绕过 SSRF）；
   - 文件上传、解压与导出下载是否校验真实内容类型、大小上限，并防范路径穿越（`../`、符号链接、Zip Slip）或可执行脚本托管；
   - 富文本/Markdown/动态 HTML 渲染是否存在存储型/反射型 XSS，状态变更接口是否缺乏 CSRF 防护或开放了过度宽松的 CORS（如反射任意 `Origin` 且允许凭据）。

4. **外部回调、OAuth 状态与防重放保护**
   - 支付通知、第三方 Webhook 或跨服务签名校验是否可被绕过（如签名为空放行、未使用常量时间比较 `hmac.compare_digest`）；
   - OAuth / SSO 登录流是否严格绑定一次性 `state` / `nonce` / PKCE，回调重定向地址（`redirect_uri`）是否存在开放重定向漏洞；
   - 关键资金、积分、权益发放或状态流转回调是否具备时间戳窗口校验与原子幂等去重锁，防止并发或网络重放双花。

5. **第三方依赖、容器与构建/CI 供应链**
   - 依赖清单是否缺少锁文件约束，或核心认证/网络/序列化组件停留在已知高危版本；
   - CI/CD 工作流（如 GitHub Actions / GitLab CI）是否存在把 PR 标题/分支名等不可信输入直插 `run:` 脚本的命令注入，或赋予过宽的默认写权限；
   - 容器构建是否以 `root` 运行业务进程，或将 `.env`、私钥、构建期凭据残留在镜像层中。

6. **AI / LLM 集成与 Agent 工具调用边界**（若项目不含 AI/LLM 模块，直接标注不适用）
   - 外部不可信文本（网页、邮件、文档、他人评论）与高权限工具调用同处一轮上下文时，是否缺乏权限降级或人工确认门禁（间接提示词注入风险）；
   - 模型生成的结构化参数、SQL、文件路径或代码片段在送入执行器/数据库/前端 DOM 前，是否经过严格白名单 Schema 与租户级沙箱校验。

## 3. 输出要求

按 `SKILL.md` 通用输出契约生成报告。每条问题的「现状与风险」需写明**具体利用前置条件与越权/受损影响面**（如“任意普通登录用户可通过修改请求体 `project_id` 读取其他租户导出文件”），「改进方案与验证方法」需给出服务端强制边界修补点及 1 条针对该越权/恶意输入的负面安全测试用例。
